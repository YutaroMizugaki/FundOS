# FundOS — プログラマブルマネーによる自律駆動型基金

ETH をプログラマブルマネーとして扱い、**人手の運営に依存せず自律的に助成金を配り続ける基金**を実装したスマートコントラクト群です。支出ポリシー・安全装置・ガバナンスのすべてがコードとしてオンチェーンに定義され、誰でも検証・執行できます。

## 全体像

```
                     寄付 (ETH)
  寄付者 ──────────────────────────► AutonomousFund(金庫)
    │  寄付額に比例した投票力を獲得       │
    │                                    │ 期日が来たら誰でも執行可能
    ▼                                    ▼
  FundGovernor(ガバナンス)          助成プログラム ──► 受給者
    提案 → 投票 → タイムロック → 執行     └─ 執行者にキーパー報酬
         │
         └── 議決結果のみが金庫の設定・助成を変更できる
```

| コントラクト | 役割 |
| --- | --- |
| `src/AutonomousFund.sol` | 金庫。寄付の受け入れ、投票力の記帳、助成プログラムの自動執行、エポック支出上限、緊急停止 |
| `src/FundGovernor.sol` | ガバナンス。提案・スナップショット投票・定足数判定・タイムロック・執行 |
| `script/Deploy.s.sol` | デプロイスクリプト。基金の統治権をガバナンスへ移譲するところまで自動化 |

## 「自律駆動」を成立させる 3 つの仕組み

### 1. パーミッションレスな執行 + キーパー報酬

助成プログラム(受給者・1 期あたりの支給額・間隔・回数)は一度ガバナンスで承認されると、以後の支払いに人間の承認は不要です。期日が来れば **誰でも** `executeGrant()` を呼んで支給を執行でき、執行者には支給額の一定割合(既定 0.1%)がキーパー報酬として支払われます。この経済的インセンティブにより、運営者が消えても基金は動き続けます。`grantDue()` ビューは Chainlink Automation / Gelato などのキーパーネットワークからそのまま利用できます。未執行のまま放置された期があっても、次の実行時にまとめて精算されます。

### 2. プロトコル層の支出上限(エポックキャップ)

すべての出金は「1 エポック(既定 30 日)あたり、エポック開始時残高の一定割合(既定 20%)まで」という制約をコントラクト自体が強制します。ガバナンスが乗っ取られたり悪意ある提案が通っても、基金全体が一度に流出することはありません。上限の変更自体もガバナンスの議決+タイムロックを要します。

### 3. 寄付 = 投票力(スナップショット方式)

寄付は取り消し不可で、1 wei = 1 投票力としてチェックポイント付きで記帳されます。投票時には提案ごとのスナップショット時点の投票力のみが有効なため、「投票開始後に大金を入れて議決を買う」攻撃ができません。投票力の取得には実際の資金拠出という不可逆なコストが伴います。

## ガバナンスのライフサイクル

1. **提案** — しきい値(既定 0.1 ETH 相当)以上の寄付実績を持つ者が、任意のコール列(助成の作成、パラメータ変更など)を提案
2. **投票遅延**(既定 1 日)— スナップショット時刻まで待機
3. **投票**(既定 5 日)— 賛成 / 反対 / 棄権。定足数は総投票力の 10%
4. **タイムロック**(既定 2 日)— 可決後もすぐには執行できず、異常時には guardian が基金を `pause()` できる猶予がある
5. **執行** — 誰でも `execute()` を呼べる。猶予期間(14 日)を過ぎた提案は失効

guardian は「緊急停止」と「助成の取り消し」のみ可能で、資金を動かす権限は一切ありません。停止解除はガバナンスの議決が必要です。

## 開発

[Foundry](https://book.getfoundry.sh/) を使用しています。

```bash
forge build          # コンパイル
forge test           # テスト (23 件)
forge test -vvv      # 詳細ログ付き
```

### デプロイ

```bash
export GUARDIAN=0x...   # 省略時はデプロイヤー
forge script script/Deploy.s.sol \
  --rpc-url $RPC_URL --private-key $PRIVATE_KEY --broadcast
```

デプロイスクリプトは基金 → ガバナンスの順にデプロイし、最後に `setGovernor()` で統治権をガバナンスコントラクトへ移譲します。以後、基金のパラメータ変更・助成作成はすべて議決を経由します。

### 主要パラメータ(デプロイ時に調整可能)

| パラメータ | 既定値 | 説明 |
| --- | --- | --- |
| `epochLength` | 30 日 | 支出上限の集計単位 |
| `epochCapBps` | 2000 (20%) | 1 エポックに支出できる残高割合 |
| `keeperBountyBps` | 10 (0.1%) | 助成執行者への報酬率 |
| `votingDelay` / `votingPeriod` | 1 日 / 5 日 | 投票スケジュール |
| `timelockDelay` | 2 日 | 可決から執行までの猶予 |
| `quorumBps` | 1000 (10%) | 定足数 |
| `proposalThreshold` | 0.1 ETH | 提案に必要な寄付実績 |

## 設計上の注意・今後の拡張

- 現在は ETH のみ対応。ERC-20(ステーブルコイン)対応は `_donate` / `_spend` を SafeERC20 に置き換える拡張で実現できます。
- 投票力は寄付累計に単調増加で、失効しません。時間減衰やクアドラティックボーティングはチェックポイント層の上に追加実装できます。
- 本コードは監査を受けていません。メインネットで実資金を扱う前に第三者監査を推奨します。
